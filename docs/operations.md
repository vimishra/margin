# Margin theory of operations

Margin does two jobs, and this document keeps them apart:

- **[Part 1: Notes](#part-1-notes)** is about writing things down and finding them again: the daily note, meetings, people, and keeping the collection tidy.
- **[Part 2: Tasks](#part-2-tasks)** is about deciding what to do and when: writing tasks, planning the day, and the weekly and monthly reviews.

Each part has its own routine for the morning, the day, the week and the month. Follow them as written for two weeks, then change what does not fit. For what each feature does, see the [user guide](user-guide.md).

Shortcuts are for the desktop app. Every one can be changed in Settings → Shortcuts.

## The day at a glance

The two routines interleave. This is the order they run in; the detail for each line is in its part.

| When | Notes | Tasks |
| --- | --- | --- |
| Morning, 5 minutes | Open the journal (⌘J) and glance at yesterday's Log | Read today's task panel, clear anything overdue, settle the Top 3 with one important item in it |
| First block of the day, 60–90 minutes | | Work on the important item, before Triage and mail |
| Late morning and mid-afternoon, 20–30 minutes each | | If you use Triage: decide on each suggestion (done, drop, or move it to its workstream), then stop |
| During the day | Capture with ⌘⇧C; link people and projects as you write | Write anything that needs doing as a task; tick things as you finish |
| Each meeting | ⌘⇧M, link who and what, bullets under Notes, then Decisions | Write each action as a task, with a due date if one was agreed |
| End of day, 2 minutes | Read down today's Log once | Tick what is done; empty the Inbox; leave the rest |
| Weekly, 20 minutes | Skim the week, refresh people notes, empty Scratch | Empty the Inbox, clear Overdue, plan from Upcoming and Anytime, catch undated tasks, give every project a next step, choose the week's focus |
| Monthly, 20 minutes | Tidy tags, notebooks and templates; back up | Review Someday, read the Logbook, close finished projects |

# Part 1: Notes

## How notes work

Four ideas carry this half.

1. **The daily note is the front door.** Everything that happens today starts there or is linked from there: a running Log, and a link to each meeting.
2. **Capture first, sort later.** Getting a thought down takes one keystroke. Deciding where it belongs happens once, at the end of the day.
3. **Link, don't file.** Write `[[Project]]` or `[[Person]]` in whatever you are writing. Each note's backlinks then show everything that mentions it, so you rarely need to move a note into the "right" folder.
4. **An area is a notebook, a project is a note.** Keep two notebooks of your own, Work and People, as Things keeps areas. Each project is one note in Work (`Work/Organization`), holding its tasks and everything else about it. Meetings that link the project have their actions listed under it in the Tasks view, so nothing needs filing. The other notebooks (Daily, Meetings, Inbox, Templates, Scratch, Assets) are Margin's own.

## Notes: every morning

1. **Open the journal: ⌘J.** Today is at the top, earlier days below.
2. **Scroll down one day** and glance at yesterday's Log, in case something there needs a follow-up today.

That is all for notes. The rest of the morning belongs to [tasks](#tasks-every-morning).

## Notes: during the day

- **Something comes to mind:** ⌘⇧C (or ⌃⌥N from any other app), type it, press Enter. It lands in today's Log with the time. Do not stop to file it.
- **You are writing about a project or a person:** link them. Type `[[` and the name.
- **You need to find something:** ⌘K and type. A name, a `#tag`, or a date such as "last friday" all work.
- **Something to keep for a few days only** (a number, a draft, a command): ⌘⌥N for a scratch note. It removes itself after a week.
- **An article or source worth reading properly:** New → Research note, and paste the link.

## Notes: every meeting

1. **As it starts: ⌘⇧M,** type the meeting's name, press Enter. The note is created, filed under Meetings by month, and linked from today's Log with the time.
2. **Fill in "Who".** Write people as links: `[[Priya Sharma]]`.
3. **Link the project** once, anywhere in the note: `[[Atlas]]`. This is what makes the meeting findable from the project later.
4. **During the meeting, write only under Notes,** as short bullets. Do not tidy as you go.
5. **In the last two minutes, fill in Decisions:** one line for each thing that was settled.
6. **Afterwards, do nothing.** The meeting is reachable from today's note, from the project's backlinks and from each person's backlinks.

Actions agreed in the meeting are tasks: see [Tasks: in a meeting](#tasks-in-a-meeting).

## Notes: every 1:1

Keep one note per person. Create it once with ⌘K → "New person note", and pin the people you meet every week.

1. **Between meetings,** whenever something comes up for that person: ⌘K, type their name, and add a line under "Next time".
2. **As the 1:1 starts,** open their note and run ⌘K → "Add today's meeting entry". A dated heading appears at the top of Meetings.
3. **Work down "Next time".** Delete each line as you cover it, and write what was said under today's entry.
4. **Before you close the note,** add anything that must wait to "Next time".

## Notes: end of the day

1. **Open today's note: ⌘D.**
2. **Read down the Log once.** For each line, ask whether it is finished, worth keeping, or something to do:
   - worth keeping: move it into the note for that project or person, or give it its own note and link it
   - something to do: make it a task (⌘⇧9); from then on it belongs to Part 2
   - finished: leave it
3. **Stop.** There is nothing to file and nothing to close.

## Notes: every week

Pick a fixed time: Friday afternoon or Monday morning.

1. **Skim the week.** ⌘J and scroll back through the week. Anything lasting that is still sitting in a Log belongs in a project or person note; move it there.
2. **Check people.** Open the note of each person you meet weekly and make sure "Next time" is current.
3. **Empty Scratch.** Open Scratch in the sidebar and press Keep on anything worth keeping. The rest expires.
4. **Close out reading.** In Research, set anything you have finished to Done.
5. **Reset the pins.** Pin what next week needs; unpin what is finished.
6. **Reshape what has grown.** A note that has turned into several topics: ⌘K → **Turn this note into a notebook** (one note per top-level heading, the note itself stays as the overview, links keep working). A section that deserves its own note: put the cursor in it, ⌘K → **Extract to a new note**. A section in the wrong note: **Move this section to another note**. Two notes about the same thing: **Merge this note into another**. Each has Undo.

## Notes: every month

1. **Tidy tags.** Look at the Tags list in the sidebar. Two tags that mean the same thing should become one: open the notes under the rarer tag and retag them (⌘T).
2. **Tidy notebooks.** A notebook with one or two notes is rarely worth having. Move those notes up a level, or merge notes that overlap (⌘K → **Merge this note into another**).
3. **Tune the templates.** If you delete the same section from every meeting note or daily note, remove it from the template in the Templates notebook.
4. **Back up.** Your notes are a folder of files. Make sure that folder is included in your backup, or copy it somewhere safe now.
5. **Update Margin** if there is a newer version on the releases page.

## Notes: where things go

| You have | Put it | How |
| --- | --- | --- |
| A passing thought | Today's Log | ⌘⇧C |
| A thing to raise with a person | Their note, under Next time | ⌘K, their name |
| What was said in a meeting | A meeting note | ⌘⇧M |
| Something needed for a few days | A scratch note | ⌘⌥N |
| An article or source | A research note | New → Research note |
| A new project | One note in Work | ⌘N in the Work notebook, named after the project |
| Lasting knowledge about a project | The project's own note | ⌘K, its name |
| Something to do | The Inbox | Quick task, ⌘⌥C |
| A meeting's actions | The meeting note, linked to its project | Write `[[Project]]` once in the meeting |

Rules of thumb:

- **If you would look for it by date,** it belongs in the daily note.
- **If you would look for it by name,** it deserves its own note.
- **When unsure, capture it.** Sorting it out is what the end-of-day read-through is for.

# Part 2: Tasks

## How tasks work

Five ideas carry this half.

1. **A task is a checkbox, and it lives where it came from.** An action from a meeting stays in that meeting's note. You never copy tasks into a list; the Tasks view and today's note gather them for you.
2. **A task has two dates, and they mean different things.**
   - The **planned day** is when you intend to start. Until then the task waits in Upcoming; from that day it sits in Today until you tick it. It never becomes overdue.
   - The **due date** is a real deadline. Only a missed due date is overdue.
3. **Someday is a parking place.** A task marked Someday stays out of Today, Upcoming and Anytime until you give it a day.
4. **The Inbox is for things you have not decided on yet.** It is one note, called Inbox, in the Inbox notebook. A task captured with Quick task, or written in that note, waits in the Inbox list and stays out of Anytime. It leaves the Inbox when you give it a day, park it in Someday, or move it into a project's note. Capturing is quick because deciding happens later, once a day.
5. **The Top 3 is today's commitment.** It is a short checklist at the top of the daily note, and what you do not finish moves to the next day by itself.

## Tasks: writing one

- **In a note:** press ⌘⇧9 on a line, or type `/task`, or write `- [ ] ` yourself.
- **From anywhere:** Quick task, ⌘⌥C (or ⌃⌥Space from another app). Type the task, with `>fri`, `@due(mon)`, `P1` or `#tag` if you already know them, and press Enter. With no day it goes to the Inbox; with a day it goes straight to Today or Upcoming.

Then add only the details the task needs. With the cursor on the task:

| Add | Key | When to use it |
| --- | --- | --- |
| A planned day | ⌘⇧S | Only if it cannot start now |
| A due date | ⌘⇧D | Only if there is a real deadline |
| A priority | ⌘⇧P | Only if it matters more than its neighbours |
| A tag | type `#name` | To gather tasks across notes |

Most tasks need none of these. A task with no dates is in Anytime, something you could do now, unless it is in the Inbox, where it waits for you to decide.

## Tasks: every morning

1. **Read the "Tasks for this day" panel** at the top of today's note (⌘J or ⌘D). It lists, from every note:
   - tasks due or planned for today
   - tasks from earlier days that are still open
   - anything overdue
2. **Deal with each overdue task.** Do one of three things: tick it, give it a new due date, or decide it is not happening and delete the line. Do not leave it overdue.
3. **Look ahead: ⌘⇧T, then 3** for Upcoming. If anything there needs to start today, highlight it and press **T**.
4. **Settle the Top 3.** In today's note, the Top 3 should hold at most three things that would make today a success. Items carried over from yesterday count. If there are more than three, push the extras to a later day: cursor on the line, ⌘⇧S, pick a day. **At least one of the three must be important work, not something from Triage;** the Focus group at the top of the note's task panel (see [Tasks: important and urgent](#tasks-important-and-urgent)) is where to pick it from.
5. **Do that important item first,** before opening Triage or mail.

## Tasks: triage

Only if a program of yours writes a triage note of suggested tasks (see the [triage guide](triage.md)). Do it in two fixed sittings of 20–30 minutes, late morning (after the first block of important work) and mid-afternoon, not whenever a new run comes in. Triage always has something in it; if it is open all day, the urgent crowds out the important (see [Tasks: important and urgent](#tasks-important-and-urgent)).

1. **Open Triage** (under Tasks in the sidebar) and read the Summary. Press **N** to have the triage note itself open on the right, following you down the list, when you want your program's full notes in view.
2. **Quick replies first.** Answer each (**O** opens the message), then **Space**.
3. **Go down the actions with ↓,** one key each: **Space** if done, **C** if you will not do it, **M** if it is real work (it moves to its workstream note, under Open Threads), **S** to give it a day, or just **↓** to leave it.
4. **A whole category is real work?** **A** moves all of it at once.
5. **Stop when what is left needs more thought.** The next run carries it over.

Reading the triage note itself instead? Its task keys do the same: ⌘↵, ⌘⌥↵, ⌘⇧S, ⌘⇧D, and ⌃⌘M to move a task by your rules.

Triage is for sorting, not doing: anything longer than a couple of minutes, move it and do it from Today or its workstream note. **C** (drop) is a good outcome, not a failure: something that is neither urgent for you nor important does not need a home. When you pick a note by hand for a category that will come again, choose it with **⌥↵** so M knows next time.

## Tasks: during the day

- **You finish something:** tick it where you see it: ⌘↵ on its line, or its checkbox in the panel.
- **You decide to do something today that was not planned:** cursor on the task, ⌘⌥T.
- **Something new needs doing:** write it as a task straight away, in the note you are in, or with Quick task (⌘⌥C, or ⌃⌥Space from another app). It lands in the Inbox; sort it at the end of the day.
- **A task turns out not to be for now:** ⌘⇧S and pick a later day, or Someday.

## Tasks: in a meeting

1. **When an action is agreed, write it at once under Action items,** as a task that starts with the owner: `- [ ] Priya: send the revised numbers`.
2. **In the last two minutes,** go down your own actions:
   - if a deadline was agreed, set it: ⌘⇧D
   - if it has to start on a particular day, set that: ⌘⇧S
3. **Afterwards, do nothing.** Your actions appear in Today or Upcoming on their own, and the task still sits in the meeting note where the context is. Because the meeting links `[[Project]]`, its actions also show under that project when the Tasks view is grouped by Project; there is no need to move them.

In a 1:1, write actions the same way under that day's entry in the person's note.

## Tasks: end of the day

1. **Tick what you finished,** in the Top 3 and in the panel. Each ticked task drops to the end of its list, so what is left stays together at the top.
2. **Leave unfinished Top 3 items alone.** They move into tomorrow's note when it is created.
3. **Leave everything else alone too.** A planned task you did not get to stays in Today tomorrow.
4. **Empty the Inbox: ⌘⇧T, then 1.** For each task, decide:
   - it has a day: **S** and pick it (**T** for today)
   - it is for some day, not soon: **S**, then Someday
   - it belongs to a project: **M** and choose the project's note. It lands under the note's "Open Threads" heading, so the threads you have filed are together at the bottom of each project. Type a new name to start a new project note.
   - it is done, or not happening: tick it, or delete the line

   Anything you cannot decide on can stay for the weekly review, but no longer than that.

## Tasks: projects

A project is anything with more than one step that ends when an outcome is reached: a launch, a hire, a move. In Margin it is one note in its area's notebook (`Work/Atlas launch`); the [user guide](user-guide.md#projects-and-areas) shows the shape of a project note.

1. **Start one** when a task turns out to need several steps. Press **M** on it in the Tasks view and type a new name, or make the note yourself with ⌘N in the right notebook.
2. **Write the outcome first,** in one line: what will be true when it is done. Then the steps you already know, under a heading for each phase. If it has a deadline, put it on the last task: `- [ ] Launch @due(2026-11-30)`.
3. **Give only the next step a day.** The rest wait in Anytime. A project with every step dated fills Today with things that cannot start yet.
4. **Let things arrive by themselves.** Tasks you file with **M** land under Open Threads. Actions in a meeting note that links the project are listed under it in the Tasks view without being moved. Sort Open Threads into the phases during the weekly review.
5. **Keep the story in the note.** Add a line to its Log when something is decided. A month later the note answers "where is this?" without a meeting.
6. **Keep it readable.** Ticked tasks collect at the end of each list. When a phase is done, or a list gets long, put the cursor under its heading and ⌘K → **Archive done tasks in this section**: they move to the Archive section at the end of the note, folded, and stay in the Logbook. To see only the outline, put the cursor on a heading and press ⇧Tab (top headings, then every heading, then everything); Tab on one heading opens its subheadings.
7. **Finish it** when the outcome is reached: tick or delete the leftovers, then ⌘K → **Move this note to the Archive**. It goes to `Archive/Work/…`, so Work holds only live projects.

The one rule that keeps projects moving: **every live project has at least one open task you could do now.** A project with none is stalled: the **Weekly review** page lists every project with its next action and flags stalled ones, so the weekly review catches them.

## Tasks: important and urgent

Triage and the Inbox bring you what is **urgent**: things other people are waiting on, with a clock attached. They arrive by themselves and clearing them feels productive. What is **important** but not urgent (the project that moves your goals, the plan nobody asked for yet, the hire, the write-up) never arrives by itself. Left alone it waits until it too becomes urgent, usually too late to do it well. The routine below gives important work its own place, time and check, so both get done.

| | Urgent | Not urgent |
| --- | --- | --- |
| **Important** | Do it today: Top 3, or Today | **Focus work:** a `#focus` next action, done in the first block of the day |
| **Not important** | Do it in a Triage sitting, quickly, or hand it on | Drop it (**C** in Triage, or delete the line) |

The danger is the top-right box: nothing in Margin or in your mail will ever ask for it. Everything below is there to protect it.

### 1. Choose the focus each week

In the weekly review (step 8 of [Tasks: every week](#tasks-every-week)), pick **two or three important outcomes** for the week: usually projects, sometimes one piece of thinking or writing. Each is a project note, or a line in one.

Open **Weekly review** (under Tasks in the sidebar). Under **Projects**, each project shows its next action; **star** the next action of each project you chose. That makes it a **focus task**: the task gets the focus tag, `#focus`:

```
- [ ] Draft the hiring plan for Q1 #focus
```

You can also press **F** on a task in the Tasks view, or type the tag yourself. Only the next action carries it, not the whole project, and only for the two or three projects you chose; the review warns when more than three projects have focus tasks. When you tick one, Margin asks for the project's next step and makes that the new focus task, so each focus project always has one.

The tag is set in Settings → General → Focus tag. A priority (`P1`) is not the same thing: priorities rank urgency within a list, while the focus tag marks what is important this week.

### 2. See it all day, above the urgent

Focus tasks are shown where urgent work is, so they are never out of sight:

- at the top of **today's daily note**, in the task panel, under **Focus**;
- at the top of **Today** in the Tasks view;
- at the top of **Triage**, so they are in view exactly when the urgent is pulling at you.

Ticking one in any of these ticks it in its project note.

### 3. Commit to one of them, first thing

When you settle the Top 3 ([Tasks: every morning](#tasks-every-morning)):

- **One of the three is a focus task,** or a piece of one ("first draft of the hiring plan's budget section"). Write it in the Top 3 with a link to the project: `- [ ] [[Q1 hiring]]: draft the budget section`. Unfinished, it carries into tomorrow's Top 3 by itself, so it stays in front of you until it is done or you decide otherwise.
- **Do it in the first block of the day,** 60 to 90 minutes, before Triage and before mail. Urgent things are rarely so urgent that they cannot wait an hour; important work rarely survives being left for "later today".
- On a day of back-to-back meetings, make the important item small (thirty minutes, one step), but keep it.

### 4. Keep Triage to its sittings

Triage is where urgent work comes in, so it is where the day slips away. Hold it to two sittings of 20 to 30 minutes ([Tasks: triage](#tasks-triage)) and stop when the time is up: what is left comes back in the next run.

In each sitting, ask of every action, **"does this belong to something important?"** If it does, **F** moves it into that project (where M would) as a focus task, so it becomes part of the important work instead of competing with it; **M** moves it without the tag. Only what is urgent and small gets done in the sitting; the rest gets a day (**S**) or is dropped (**C**).

### 5. Check the balance each week

**Weekly review** does the counting:

1. **The week** shows how many tasks you finished, how many were focus work, and how many were completed in Triage, and says plainly when almost none was focus work. If that happens, protect the first blocks harder next week, or cut the focus into smaller next actions.
2. **Focus now** marks any focus task that has **not moved in two weeks**. Such a task is either too vague (rewrite it as something you could start in five minutes) or not actually important (press F on it to take it out of focus, and let it go back to Anytime or Someday). Both are fine decisions; leaving it stuck is not.
3. **Projects** flags **stalled** projects, with no open task: write the next step, or archive it if it is finished. Then star next week's focus (step 1).

### What each part of Margin is for

| | Holds | When |
| --- | --- | --- |
| Daily note: Top 3 and Focus | Today's commitment, with one important item; the week's focus next actions | First thing; important item in the first block |
| Triage | Urgent work as it comes in | Two short sittings a day, after the first block |
| Inbox | Things you have not decided on | Emptied at the end of the day |
| Project notes | Important work, its steps and its story; the threads Triage sends there | Weekly review, and whenever you work on it |
| Weekly review (the page) | The balance between the two, stuck focus tasks, stalled projects, and next week's focus | Once a week |

## Tasks: every week

This is the review that keeps the lists trustworthy. Open the Tasks view: ⌘⇧T.

1. **Empty the Inbox: press 1,** as at the end of a day. Nothing should be left in it after the review.
2. **Clear what is overdue: press 7.** For each task: do it, give it a new date, or delete it. To push a batch to one day, use **Move all…**.
3. **Read what is coming: press 3** for Upcoming.
4. **Plan the week: press 4** for Anytime, which is everything you could start now.
   - For each thing you intend to do this week, press S and give it a day.
   - For each thing you are not going to do soon, press S and choose Someday.
5. **Catch undated strays: press 9** for No date. Anything here has no plan: give it a day, send it to Someday, or delete it.
6. **Archive what is finished.** In the Logbook (press 6), **Archive done tasks…** moves everything ticked over a week ago into each note's Archive section, so project and people notes show what is still open.
7. **Check every project has a next step.** Open **Weekly review** (under Tasks): its **Projects** list shows each project's next action and marks those with none as **Stalled**, with buttons to write the next step or archive the note. (Or press 4 for Anytime and group by **Project**.) Each should show at least one open task. For one that shows none, open its note and write the next step, or, if it is finished or dropped, archive it. Sort any tasks waiting under a project's Open Threads into its phases while you are there.
8. **Check the balance and choose next week's focus.** Open **Weekly review** (under Tasks): read how much of the week was focus work, deal with focus tasks that have not moved and with stalled projects, and star the next actions of the two or three projects that matter next week. See [Tasks: important and urgent](#tasks-important-and-urgent). (Step 7's check is on the same page, under Projects.)

## Tasks: every month

1. **Review Someday: ⌘⇧T, then 5.** For each item: give it a real day, leave it, or delete it. This list is only useful if it is short enough to read.
2. **Read the Logbook: press 6,** grouped by date. Scan what you finished this month. It is the easiest source for a status update or a review.
3. **Close finished projects.** Group the Tasks view by Project. A note whose tasks are all done or all stale is a project that has ended: tick or delete the leftovers, then open it and ⌘K → **Move this note to the Archive**, so Work holds only live projects.
4. **Check your saved filters.** Remove the ones you no longer open.

| What to do today | Today | 2 |
| What starts later | Upcoming | 3 |

**From a terminal or a script:** `margin-tasks` prints the same lists, for example `margin-tasks today`, `margin-tasks inbox` or `margin-tasks overdue --count`. Install it from Help → Command-Line Tool…; it goes into `~/.local/bin` and needs no password. The user guide lists every option.

To see one project's tasks, group by Project. To see one topic across projects, type its `#tag` in the narrow-down box, and save it as a filter if you will want it again.

In the Tasks view (⌘⇧T), on the highlighted task:

| Do this | Key |
| --- | --- |
| Move between tasks | ↑ ↓ |
| Tick or untick | Space |
| Move to today | T |
| When | S |
| Due date | D |
| Priority | P |
| Move it into another note (a project) | M |
| Make it a focus task, or take it out | F |
| Open it in its note | ↵ |
| Narrow the list | / |
